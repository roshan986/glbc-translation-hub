17. RESOLUTION OF CHAT AUTHOR RECOGNITION IN MULTI-MEMBER COMMITTEE DISCUSSIONS (18:15 IST)

Item 1: Root Cause of "All Messages Appearing as 'You'"
- User Observation (testing.docx Batch 8):
  * Logged in as Pastor Matt: Every single message (even messages sent by Pastor Zack) shows on the right as "You (Committee)" with avatar PM.
  * Logged in as Pastor Zack: Every single message (even messages sent by Pastor Matt) shows on the right as "You (Committee)" with avatar PZ.
  * In Google Sheets Column O: Bylines are recorded accurately:
    "Pastor Zack: Hello, why is the delay?"
    "Pastor Zack: Hello"
    "Pastor Matt: Please make it fast"
    "Pastor Matt: I think we need time"
  * User Query: "Is this because we have to correctly configure or are we tracking this on who has logged in concept or there is something that I don’t understand? May be tracking from google sheet is vague? Explain me."

- Root Cause Analysis (Google Sheets is 100% Accurate):
  * Tracking from Google Sheets is NOT vague. Google Sheets reliably records the author prefix (`Pastor Zack:`, `Pastor Matt:`) in Column O.
  * The frontend parser `parseAllReviewsToComments()` in `web/src/utils/commentSync.ts` correctly parsed each block into:
    - Comment 1 & 2: `authorName: "Pastor Zack"`, `authorRole: "Committee"`
    - Comment 3 & 4: `authorName: "Pastor Matt"`, `authorRole: "Committee"`
  * The BUG was entirely in the frontend condition determining whether a comment was sent by "Me":
    ```tsx
    const isMe = Boolean(
      currentUser &&
      ((cmt.authorName && cmt.authorName.toLowerCase().trim() === currentUser.name.toLowerCase().trim()) ||
        (currentUser.email && cmt.authorRole && cmt.authorRole.toLowerCase().includes('comm')))
    );
    ```
  * In the Committee tab, `cmt.authorRole` is always `"Committee"`, and any logged-in user has `currentUser.email`.
  * Therefore, the second part of the `||` check was ALWAYS TRUE for every message in the deliberation thread!
  * This forced `isMe = true` for all comments, rendering every message on the right with the logged-in user's name and initials.

Item 2: Applied Solution
- In `web/src/utils/userUtils.ts`:
  * Implemented `isCommentByCurrentUser(cmtAuthor?: string, currentUserName?: string): boolean`
  * Strictly compares author names with smart honorific normalization (handling both "Pastor Zack" and "Zack").
- In `web/src/components/FocusModeCard.tsx`:
  * Imported `isCommentByCurrentUser` and updated both the Committee deliberation loop and Discipline review loop:
    `const isMe = isCommentByCurrentUser(cmt.authorName, currentUser?.name);`
  * Avatar and byline titles now accurately display the actual comment author when `isMe` is false, and "You" when `isMe` is true.
- In `web/src/components/DiscussionPopoutModal.tsx`:
  * Replaced the fallback with `isCommentByCurrentUser(cmt.authorName, currentUser?.name);`.
